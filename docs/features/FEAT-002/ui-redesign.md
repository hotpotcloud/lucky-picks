# UI 重构方案

状态：方案与视觉概念稿已形成，整体 UI 重构尚未实施。API 接入和注册修复独立交付，不代表本方案全部完成。

## 1. 需求与设计输入

- 保留暗黑科技风，重写主页面交互和走势图，呈现现代、精致的视觉效果。
- 组件统一使用 shadcn/ui，沿用 React、Vite、Tailwind 现有技术栈。
- 主页面的奇偶、大小、和值、三区允许用户手动设置，不设置时沿用当前默认策略。
- 前端接入真实后端，邀请注册、登录、历史数据、推荐调用 API，不用模拟结果掩盖失败。
- 注册采用邀请制：已有用户登录后生成邀请码，摘要写入数据库；新用户注册必须提交有效邀请码，成功后一次性核销。

设计稿：[桌面选号工作台](../../../frontend/assets/design/number-workbench-design.png)。图片用于布局与风格参考，号码、注数、金额及模式选中状态为示意，落地以业务规则为准。

## 2. 当前问题

- 选号、结果、本地历史纵向堆叠，桌面空间利用不足，操作与反馈分离。
- 玩法、模式、机选填充、生成按钮缺少清晰层级。
- 大面积磨玻璃与同样的高亮边框使所有卡片具有接近的视觉权重。
- 当前号码走势图固定 33 列，缺少区域配置、表头、图例与行列定位。
- 频率图缺少号码刻度、悬浮详情及期望参考线。
- shadcn 基础组件与 Ant Design 主页面混用，主题和控件状态不统一。

## 3. 视觉系统

方向：深色精密选号工作台。号码与数据是视觉中心，导航和说明保持安静。

- 页面背景 `#090C10`；面板 `#11161D`；浮层 `#19212B`。
- 边框 `#283240`；主文字 `#F2F5F8`；次文字 `#A1ADBB`。
- 主操作青绿 `#2DD4BF`；号码红 `#FB7185`；附加号码蓝 `#60A5FA`；胆码金 `#FBBF24`。
- 颜色配置为语义变量，组件中不散落硬编码色值。最终检查 WCAG AA 对比度。
- 普通面板采用实底；透明与模糊限于导航和浮层等少数位置。
- 正文 14–16px，说明不低于 12px，标题 26–30px，区块标题 16–18px。
- 数字等宽；号码两位补零；日期、金额、期号保持对齐。
- 间距使用 4、8、12、16、24、32px；控件圆角 8px，面板 14px，浮层 16px。

## 4. 页面结构

### 4.1 应用框架

顶部 64px 导航包含品牌、选号工作台、智能推荐、历史数据、数据分析和用户菜单。导航下方放置玩法切换、最新期号与数据状态，所有功能共享当前玩法上下文。

没有数据时显示空状态，不填充示例期号或模拟数量。错误状态应说明原因并提供重试路径。

### 4.2 主页面

桌面内容最大宽度约 1440px，操作区占 60%–65%，结果区占 35%–40%，间距 24px。本地记录位于工作区下方，仅默认展示最近记录。

操作区顺序：模式 → 策略与注数 → 可选手动条件 → 选号/生成 → 校验反馈。结果区顺序：玩法与模式 → 注数金额 → 号码列表 → 复制和保存。

单式、复式、胆拖使用 Tabs。每种模式只显示相应参数。涉及清空已选内容的模式切换应明确反馈，遵守既有业务规则。

### 4.3 号码控件

- 可点击号码至少 44×44px；悬浮、选中、焦点和禁用状态清晰。
- 胆码使用金色与“胆”标记，拖码使用区域色与“拖”标记，不只依赖颜色。
- 区域标题显示规则和已选数量，提供区域级清空、机选补齐。
- 选号按钮与结果号码区分尺寸，前者强调交互，后者强调阅读。

## 5. 手动分析条件

### 5.1 输入与默认值

用户所举“奇偶 3:3、大小 3:3、和值 103、三区 2:2:2”是可设置的例子，不作为所有玩法的固定默认值。

单式机选增加“手动条件（可选）”区域：

- 奇偶：输入奇数数量，偶数数量根据主区总数联动显示，标明“奇:偶”。
- 大小：输入大号数量，小号数量联动显示，标明“大:小”。
- 和值：输入目标整数；例如 103 表示主区号码总和精确为 103。
- 三区：分别输入一区、二区、三区数量，总数必须等于当前玩法的主区号码数量。
- 每项可保持空白或清除；未设置的字段不发送约束，沿用现有策略。
- 提供恢复默认操作，清除手动覆盖，不修改全局算法。

这些条件控制生成过程，结果中的四个指标仍由实际号码计算，不能把用户输入直接当作结果标签。

### 5.2 约束与规则

- 仅约束主区，附加区继续遵守玩法规则。
- 奇数与大号数量为 0 到主区单注数量的整数。
- 大小与三区边界复用现有规则，输入旁可查看范围说明。
- 和值限定在当前主区合法单注的理论最小值和最大值之间。
- 三区需要三个值完整填写；每区数量不能超过该区可选号码数。
- 用户设置的条件作为硬约束；无匹配结果时明确提示放宽条件，不静默忽略。
- 生成尝试有上限，不允许无限重试或冻结页面。
- 切换玩法清空手动条件，避免红蓝玩法的六个号码比例被带入前后玩法。
- 首期用于单式机选；复式和胆拖不自动过滤或更改用户已选集合。

### 5.3 API 映射

复用推荐接口的 `constraints`：奇偶映射 `oddEven=[奇数数量,奇数数量]`，大小映射 `bigSmall=[大号数量,大号数量]`，和值映射 `sumRange=[目标和值,目标和值]`。

新增可选 `zoneCounts=[一区数量,二区数量,三区数量]`，表达精确比例；保留已有 `zones` 的区间语义，不能将两者混用。所有未设置字段省略。

## 6. 结果、本地记录与推荐

登录表单默认隐藏：页面右上角只保留淡色财神水印，连续点击两次后以 900ms 缓动动画展开登录框，水印同时移入登录框空白区域；水印无 hover 效果。注册表单包含账号、密码、邀请码；不提供无邀请码的开放注册。登录后用户菜单提供生成邀请码与复制操作，接口返回后展示明文，页面不持久化邀请码。失败时保留表单并提示原因。

登录与注册不在请求体中传输明文密码：浏览器计算 `sha256("lucky-picks:v1:" + username + ":" + password)`，后端只接收 64 位摘要，并以 PBKDF2 加盐存储。注册额外提交密码长度用于服务端长度校验。未启用 HTTPS 时摘要仍可能被链路上窃听重放，因此该方案只解决明文泄露与跨站密码复用，生产环境仍应尽快启用 TLS。

结果区突出首注，其余采用紧凑列表，避免逐注大卡片。显示总注数、金额、预览上限，复制与保存给出明确反馈。

历史数据指后端历史期次，本地记录指用户选号记录，名称和入口分开。现有存储兼容性保持稳定。

推荐区统一策略、注数与高级参数的层级。接口失败展示错误，不能生成本地简化结果冒充后端推荐。生成很快时不人为延时。

## 7. 走势图

### 7.1 数据表达

采用号码矩阵：顶部号码表头、左侧固定期号、内部横向滚动。列数根据玩法与区域配置生成，支持主区与附加区切换。

默认近期 30 期，期数选项与可用数据量匹配。实际不足时明确显示真实样本数。

每五列、每十行增加弱分组线，命中使用醒目圆点，其余保持低对比度。桌面单元宽 28–32px，行高 30–36px。

### 7.2 交互

- 悬浮/聚焦高亮当前期号行和号码列，详情显示期号、日期、号码、命中状态。
- 点击表头可锁定号码列，再次点击取消。
- 移动端点击查看详情，保留固定表头和期号。
- 提供密度切换、图例和文本/表格替代视图。
- 默认不把不同期的任意号码连线；如展示位置走势，必须标注排序位置定义。
- 遗漏数字作为后续增强，基于可用完整历史计算，窗口截断处明确边界。

## 8. 频率与分析

频率图展示号码横轴、次数纵轴、理论期望线、Tooltip 和号码/频率排序。主区与附加区使用各自范围、选取数量和统计样本。

冷热同时使用文字说明，不与红蓝区域语义混淆。分析页面按样本摘要 → 主图 → 冷热遗漏明细 → 解读组织。AI 解读作为次级内容，不扩展接口能力。

## 9. 组件与动效

复用现有 Button、Input、Card、cn、Tailwind、Lucide；按需增加 Tabs、Select、ToggleGroup、Tooltip、Popover、Sheet、Dialog、Table、Skeleton 与通知组件。

走势矩阵使用业务网格与必要 SVG；频率图评估 shadcn Chart + Recharts。依赖清单单独确认，不为视觉改版升级框架主版本。

按钮反馈 120–160ms，切换 160–200ms，面板进入 200–260ms，抽屉 220–280ms。优先 transform/opacity，遵守减少动态效果偏好。

## 10. 响应式与验收

- ≥1280px 双栏；中屏按空间调整；<768px 单列，结果紧随操作。
- 360px 页面不横向溢出；走势图仅在自身容器内部滚动。
- 键盘完成核心操作，焦点清楚，表单有 label，图表有文本替代。
- 自动化覆盖模式切换、约束默认与覆盖、非法输入、无法匹配、真实请求与错误反馈。
- 检查 `pnpm check:terms`、`pnpm lint`、`pnpm typecheck`、`pnpm test`、`pnpm build`。
- 实施与 AI 评审分会话，需求提出方确认视觉验收。

## 11. 任务拆分

1. 主题变量和基础组件。
2. 顶部导航、玩法上下文与双栏框架。
3. 模式控件和号码状态。
4. 单式手动条件与后端约束。
5. 结果区与本地记录。
6. 配置驱动走势矩阵。
7. 行列联动、浮层和移动端图表。
8. 频率图与分析明细。
9. 推荐、历史和登录界面统一。
10. 全链路回归与视觉验收。

每项连同必要测试不超过 400 行有效改动，超过继续拆分。当前真实 API/注册修复不顺带实现其余视觉任务。
