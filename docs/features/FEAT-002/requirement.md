## 1. 背景与目标

v1（FEAT-001）是纯前端随机/均衡选号工具，没有历史数据、没有后端、玩法只有基础机选/简单复式/单区胆拖。FEAT-002 要在保持「不承诺中奖」的前提下，补齐数据、算法、全玩法与后端能力：

1. 接入官方公开开奖数据，前端可查看历史开奖与统计数据。
2. 提供透明、可解释、可复现、可回测的号码推荐算法，并与随机基线对比。
3. 支持红蓝玩法、前后玩法的官方全部投注形式：单式、复式（含分区复式）、胆拖（含分区胆拖）、追加（前后玩法）、多倍。
4. 新增 Python FastAPI 后端，规则计算与推荐算法以服务端为准。
5. 调研同类开源项目，把值得借鉴的能力整理为 FEAT-003。

成功标准：

- 官方规则覆盖完整，金额/注数与官方规则一致，超限有明确提示。
- 数据可自动更新，失败可降级，页面能看到数据更新时间与来源。
- 推荐结果合法、可复现（同一数据版本+同一 seed 结果一致）、有解释、可一键带入选号单。
- 回测能把「策略 vs 随机基线」的命中分布、投入产出、样本量与置信区间展示清楚。
- 页面明确说明：开奖结果为独立随机事件，任何算法都不能提高单注期望，推荐仅供娱乐参考。

## 2. 使用者与场景

- 想查看最近开奖、号码冷热与遗漏的普通用户。
- 想按单式/复式/胆拖/追加/倍数组合投注，但不想手算注数与金额的用户。
- 想对比不同选号策略历史表现、验证「冷热号是否有效」的用户。
- 开发者/研究者：希望复用 API、回测与数据管道。

## 3. 范围

### 3.1 本次要做

- **数据**：官方数据源 A（红蓝玩法）与官方数据源 B（前后玩法）公开数据抓取、规范化、去重、持久化、定时更新与失败降级。
- **后端**：FastAPI 服务，提供规则配置、开奖数据、统计、选号校验、推荐、回测接口。
- **全玩法**：
  - 红蓝玩法：单式、红球复式、蓝球复式、全复式、单式胆拖、复式胆拖、多倍。
  - 前后玩法：单式、前区复式、后区复式、双区复式、前区胆拖、后区胆拖、双区胆拖、追加、多倍。
  - 金额上限：红蓝玩法单票 ≤ 20000 元；前后玩法基本投注单票 ≤ 20000 元、基本+追加 ≤ 30000 元。
- **推荐算法**：统计特征 + 约束采样 + 覆盖设计 + 回测；策略预设、解释、可复现 seed。
- **前端**：选号工作台（全玩法）、智能推荐、历史开奖、数据分析、回测、玩法说明。
- **调研**：算法调研文档、开源项目对比、FEAT-003 需求清单。
- **部署**：后端可部署（Docker/Render 方案），前端继续 GitHub Pages，接口地址可配置。

### 3.2 本次不做

- 不接入任何非官方或未授权的第三方开奖数据源。
- 不做真实投注、代购、支付、兑奖、资金流。
- 不做用户账号、云端同步、个人信息采集。
- 不承诺「预测中奖」，不展示「必中」「稳赚」「AI 预测准确率」等误导性表述。
- 不在 FEAT-002 内落地深度学习模型训练（LSTM/Transformer/XGBoost 等），只在调研与回测框架中预留接口，作为 FEAT-003 评估项。
- 不做多期投注（官方规则未明确支持，且涉及销售系统差异）。
- 不实现自动购买或任何绕过官方渠道的能力。

## 4. 官方业务规则（已核对）

数据与规则核对日期：2026-11-23。

### 4.1 红蓝玩法

| 项 | 规则 |
|---|---|
| 号码区 | 红球 1–33，蓝球 1–16 |
| 单式 | 6 红 + 1 蓝，2 元/注 |
| 红球复式 | 红 7–33 个（实现上限见 4.3），蓝 1 个 |
| 蓝球复式 | 红 6 个，蓝 2–16 个 |
| 全复式 | 红 ≥7 个，蓝 ≥2 个 |
| 单式胆拖 | 红胆 1–5 个，胆+拖 ≥7；蓝 1 个 |
| 复式胆拖 | 红胆 1–5 个，胆+拖 ≥7；蓝 ≥2 个 |
| 多倍 | 2–99 倍（1 倍即不倍投） |
| 单票上限 | ≤ 20000 元 |
| 开奖 | 每周二、四、日（以官方公告为准） |

### 4.2 前后玩法

| 项 | 规则 |
|---|---|
| 号码区 | 前区 1–35，后区 1–12 |
| 单式 | 5 前 + 2 后，基本 2 元/注；追加 +1 元/注 |
| 前区复式 | 前 ≥6 个，后 2 个 |
| 后区复式 | 前 5 个，后 ≥3 个 |
| 双区复式 | 前 ≥6 个，后 ≥3 个 |
| 前区胆拖 | 前胆 1–4 个，胆+拖 ≥6；后 2 个 |
| 后区胆拖 | 前 5 个；后胆 1 个，后拖 ≥2 个 |
| 双区胆拖 | 前胆 1–4 个；后胆 1 个 + 后拖 ≥2 个 |
| 追加 | 复式/胆拖均可按注追加，每注 +1 元 |
| 多倍 | 2–99 倍 |
| 单票上限 | 基本 ≤20000 元；基本+追加 ≤30000 元 |
| 开奖 | 每周一、三、六（以官方公告为准） |

### 4.3 实现约束与说明

- 规则文件只以官方金额上限与组合数学做硬校验；不自行发明「最多选 20 个」之类的官方未写明限制。
- 前端为避免一次渲染/枚举过多组合，展示与「一键带入」限制前 100 注预览；真实注数、金额由后端计算，不受预览限制。
- 推荐与回测同样受单票金额上限约束。
- 官方来源：
  - 红蓝玩法游戏规则：<https://www.cwl.gov.cn/c/2026/01/29/417937.shtml>
  - 官方数据源 B 公开规则文件：<https://www.lottery.gov.cn/bzzx/yxgz/20191119/1002858.html>
  - 官方数据源 A 开奖查询接口（服务端使用）：`https://www.cwl.gov.cn/cwl_admin/front/cwlkj/search/kjxx/findDrawNotice`
  - 官方数据源 B 开奖查询接口（服务端使用）：`https://webapi.sporttery.cn/gateway/lottery/getHistoryPageListV1.qry`

## 5. 功能需求

- REQ-101 支持红蓝玩法、前后玩法切换；规则、号码区、玩法、金额上限同步变化。
- REQ-102 支持单式/复式/胆拖三种模式，并按玩法展示官方允许的分区复式/分区胆拖。
- REQ-103 支持前后玩法追加投注与所有玩法的多倍投注；实时计算注数、基本金额、追加金额、总金额。
- REQ-104 金额超过官方单票上限、组合非法、胆拖数量非法时，前端禁用提交并展示具体原因；后端返回同样的校验错误。
- REQ-105 提供最新开奖、历史开奖列表（分页）、按期号/日期筛选；展示数据来源与更新时间。
- REQ-106 提供统计：号码频率、冷热排名、当前/最大遗漏、期望遗漏、奇偶/大小/和值/跨度/三区/AC 值分布、卡方均匀性检验。
- REQ-107 提供推荐：策略预设（均衡、热号、冷号、遗漏、贝叶斯综合、覆盖设计）、统计窗口、注数、约束（奇偶/大小/和值/跨度/连号/区间）、seed。
- REQ-108 推荐结果包含：号码、模式、注数、金额、策略解释（每个号码的主要特征贡献）、数据版本、随机种子。
- REQ-109 推荐结果可一键带入选号工作台，可保存到本地历史；保存内容包含玩法、倍数、追加、金额快照。
- REQ-110 提供回测：按策略在历史窗口上滚动生成号码，统计各奖级命中次数、命中率、投入、回报、ROI，并与随机基线对比，附样本量与置信区间。
- REQ-111 页面固定展示免责声明与「算法不改变单注期望」的说明；禁止出现「必中」「稳赚」「提高中奖率」等表述。
- REQ-112 后端不可用/冷启动/接口失败时，前端展示可重试的错误态；历史开奖与推荐可降级到最近一次成功缓存（只读）。
- REQ-113 后端提供健康检查、请求 ID、结构化日志、CORS 白名单与基础限流。
- REQ-114 数据抓取失败不覆盖旧数据；记录抓取时间、来源、成功/失败原因；数据更新对用户可见。
- REQ-115 代码与文档可追溯：FEAT-002 需求、设计、契约、任务、测试、验收记录齐全。
- REQ-116 术语合规：仓库内（代码、注释、界面文案、文档、元数据、仓库描述）不得出现真实游戏名称及其等价写法，统一使用「红蓝玩法 / 前后玩法 / 选号 / 官方数据源 A|B」；由 `frontend/scripts/check-terminology.mjs` 强制校验，CI 阻断。

## 6. 非功能需求

- 性能：窗口 ≤300 期时，`/stats` p95 < 500ms；`/recommendations`（5 注）p95 < 800ms；回测 100 期 × 5 注 p95 < 3s（免费实例可放宽，前端有 loading）。
- 可用性：后端冷启动期间前端展示「服务唤醒中」；关键页面有 loading/空/错误/离线状态。
- 数据量：红蓝玩法/前后玩法历史各保留至少 500 期，默认返回最近 30 期，单页最大 100 期。
- 安全：无账号、无个人信息；不提交密钥；CORS 仅允许配置的前端域名；对外接口只读 + 无状态计算；限流防滥用。
- 合规：仅抓取官方公开页面/接口，低频（每日或开奖后一次），标注来源；不提供投注服务。
- 可观测：日志包含 requestId、game、window、strategy、耗时、错误堆栈；敏感信息不落日志。
- 可测试：规则、统计、推荐、回测全部为可单测的纯逻辑；数据适配器用固定 fixture；契约测试校验响应。

## 7. 推荐算法原则

1. **不改变期望**：开奖结果为独立随机事件，任何排序/组合方法都不改变单注期望，产品只做「号码筛选与组合优化」。
2. **透明**：每个推荐号码给出特征贡献；策略权重公开可查。
3. **可复现**：同一数据版本 + 同一 seed + 同一参数，结果一致。
4. **可验证**：必须能与随机基线对比；不以「命中一次」作为有效性证据。
5. **约束优先**：任何推荐必须满足玩法合法性与金额上限。
6. **多样性**：多注推荐避免重复号码组合，必要时用覆盖设计/贪心覆盖。

## 9. 核心用例（TC-101 起）

- TC-101（核心）数据抓取：给定官方接口返回，规范化后入库，期号唯一、号码范围正确、重复抓取不产生重复记录。
- TC-102（核心）数据降级：官方接口超时/返回异常时保留旧数据，`dataUpdatedAt` 不变，接口仍可用。
- TC-103（核心）红蓝玩法全玩法：红复式、蓝复式、全复式、单式胆拖、复式胆拖的注数与金额与官方规则一致。
- TC-104（核心）前后玩法全玩法：前/后/双区复式、前/后/双区胆拖、追加、倍数的注数与金额正确。
- TC-105（核心）金额上限：超过红蓝玩法 20000 元、前后玩法基本 20000/含追加 30000 元时被拦截。
- TC-106（核心）非法参数：胆码过多、胆码与拖码重复、拖码不足、号码超范围、空选均被拦截并给出原因。
- TC-107（核心）统计正确：固定数据集下频率、遗漏、期望遗漏、和值/跨度/奇偶/大小/三区/AC 值与手工计算一致。
- TC-108（核心）推荐合法：任意策略生成的号码满足玩法规则、金额上限、约束条件，且注间不重复。
- TC-109（核心）推荐可复现：同数据版本、同 seed、同参数两次结果一致；不同 seed 结果不同。
- TC-110（核心）推荐解释：每个号码至少有一个特征贡献，权重与策略一致。
- TC-111（核心）回测：合成数据集上奖级判定、投入、回报、ROI、命中率与手工计算一致；随机基线可复现。
- TC-112（核心）冷热策略差异：在构造的偏态数据上，热号/冷号/遗漏策略的选号倾向符合定义。
- TC-113（核心）一键带入：推荐结果带入选号工作台后，玩法、号码、追加、倍数、金额与推荐一致。
- TC-114（核心）免责声明：页面展示「不改变单注期望」「不承诺中奖」，无「必中/稳赚/提高中奖率」文案。
- TC-115（边界）后端冷启动：前端显示唤醒提示与重试，恢复后数据正常。
- TC-116（异常）接口 4xx/5xx：前端展示错误码与可操作提示，不白屏。
- TC-117（核心）契约一致：后端响应与 `docs/contracts/openapi.yaml` 一致，前端类型由契约生成且无手改。
- TC-118（边界）大数据量：窗口 300 期、历史分页、100 注预览下页面可用，无卡死。
- TC-119（核心）响应式：360px 宽度下选号、推荐、历史、统计可操作，无横向滚动。
- TC-120（边界）推荐历史：保存/删除/清空与金额快照正确，存储异常降级。
- TC-121（核心）术语合规：`pnpm check:terms` 通过；界面、文档、仓库描述中无受限字样；新增受限词会被 CI 阻断。
