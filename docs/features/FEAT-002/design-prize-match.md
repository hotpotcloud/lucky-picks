# 机选号码历史中奖匹配设计

## 1. 背景与目标

用户机选号码后，目前只能看到号码本身，无法判断这组号码如果在最近若干期开奖中投注，会命中
什么奖级。本次增加“历史中奖匹配”能力：

- 生成号码后，用该号码逐期对比数据库中的历史开奖记录。
- 默认匹配最近 50 期，可切换到 100 / 200 / 300 期。
- 标出每一期的主区命中数、副区命中数、对应奖级和奖金。
- 给出汇总：最佳奖级、中奖期数、各奖级命中次数。
- 在界面展示当前玩法的中奖规则，规则和判定逻辑由后端统一提供，前端不硬编码。

历史匹配只做回顾展示，不代表未来开奖结果，不承诺中奖。

## 2. 范围

### 2.1 本期范围

- 红蓝玩法、前后玩法的单注号码匹配。
- 机选生成的多注单式号码逐注匹配。
- 复式和胆拖方案按组合展开后匹配，但设置组合数上限。
- 最近 50 期默认窗口，最大 300 期。
- 奖级规则接口和前端规则展示。

### 2.2 不在本期范围

- 追加投注的追加奖金计算。
- 浮动奖的真实派奖金额；一、二等奖继续使用估算值并标记 `estimated=true`。
- 历史开奖数据回填、实时数据源变更。
- 把历史命中率包装成预测能力。

## 3. 现有能力复用

奖级判定已经存在于 `backend/app/games/prizes.py`：

- `evaluate(game, main_hit, extra_hit)` 返回奖级名称、奖金和是否估算。
- 回测服务 `backend/app/backtest/service.py` 已使用同一函数。

本次不复制奖级规则，新增匹配服务直接调用 `evaluate`，保证回测、历史匹配和规则展示三处一致。

## 4. 中奖规则

### 4.1 红蓝玩法

| 奖级 | 条件（主区命中 + 副区命中） | 奖金（元） | 说明 |
|---|---|---:|---|
| 一等奖 | 6 + 1 | 5,000,000 | 浮动奖，估算 |
| 二等奖 | 6 + 0 | 100,000 | 浮动奖，估算 |
| 三等奖 | 5 + 1 | 3,000 | 固定 |
| 四等奖 | 5 + 0 或 4 + 1 | 200 | 固定 |
| 五等奖 | 4 + 0 或 3 + 1 | 10 | 固定 |
| 六等奖 | 2 + 1、1 + 1、0 + 1 | 5 | 固定 |

### 4.2 前后玩法

| 奖级 | 条件（前区命中 + 后区命中） | 奖金（元） | 说明 |
|---|---|---:|---|
| 一等奖 | 5 + 2 | 10,000,000 | 浮动奖，估算 |
| 二等奖 | 5 + 1 | 300,000 | 浮动奖，估算 |
| 三等奖 | 5 + 0 | 10,000 | 固定 |
| 四等奖 | 4 + 2 | 3,000 | 固定 |
| 五等奖 | 4 + 1 | 300 | 固定 |
| 六等奖 | 3 + 2 | 200 | 固定 |
| 七等奖 | 4 + 0 | 100 | 固定 |
| 八等奖 | 3 + 1 或 2 + 2 | 15 | 固定 |
| 九等奖 | 3 + 0、2 + 1、1 + 2、0 + 2 | 5 | 固定 |

规则来源为 `backend/app/games/prizes.py`，接口返回时直接携带条件和奖金，避免前端复制一份规则。

## 5. 匹配模型

### 5.1 单注匹配

对每个号码集合：

1. 主区命中数 = 投注主区号码集合与开奖主区号码集合的交集大小。
2. 副区命中数 = 投注副区号码集合与开奖副区号码集合的交集大小。
3. 调用 `evaluate(game, main_hit, extra_hit)` 得到奖级；未命中返回 `null`。
4. 按开奖期号倒序写入匹配明细。

### 5.2 多注、复式与胆拖

- 单式多注：逐注匹配，返回每注各自的结果和整体最佳奖级。
- 复式：按区域规则展开组合，最多展开 `MATCH_MAX_COMBINATIONS = 10000` 注。
- 胆拖：胆码固定、拖码组合，同样受 10000 注上限约束。
- 超过上限时不静默截断，返回 `COMBINATION_TOO_LARGE`，提示减少选号或改用单式。
- 每期展示“该期最佳奖级”，同时返回该期命中奖级的组合数量。

### 5.3 窗口

- 默认 `window=50`。
- 允许 `1–300`，与统计接口的最大窗口保持一致。
- 查询条件：`game` + 按 `issue` 倒序，取最近 `window` 期。
- 数据不足时返回实际 `drawCount`，前端展示“实际匹配 N 期”。

## 6. 接口设计

### 6.1 获取中奖规则

`GET /api/v1/games/{game}/prizes`

响应示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "game": "redblue",
    "price": 2,
    "prizes": [
      {
        "level": 1,
        "name": "一等奖",
        "amount": 5000000,
        "estimated": true,
        "conditions": [{ "mainHit": 6, "extraHit": 1 }]
      }
    ]
  }
}
```

### 6.2 历史匹配

`POST /api/v1/prize-matches`，需要登录。

请求：

```json
{
  "game": "redblue",
  "window": 50,
  "tickets": [
    {
      "mode": "single",
      "areas": [
        { "key": "red", "numbers": [1, 5, 9, 14, 22, 31], "banker": [] },
        { "key": "blue", "numbers": [7], "banker": [] }
      ]
    }
  ]
}
```

响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "game": "redblue",
    "window": 50,
    "drawCount": 50,
    "summary": {
      "bestPrize": "五等奖",
      "bestAmount": 10,
      "winningDraws": 3,
      "winRate": 0.06,
      "prizeCounts": { "五等奖": 2, "六等奖": 1 },
      "estimated": false
    },
    "tickets": [
      {
        "index": 0,
        "bestPrize": "五等奖",
        "matches": [
          {
            "issue": "2026110",
            "date": "2026-09-21",
            "mainHit": 3,
            "extraHit": 1,
            "prize": { "name": "五等奖", "amount": 10, "estimated": false },
            "combinationHits": 1
          },
          {
            "issue": "2026109",
            "date": "2026-09-19",
            "mainHit": 1,
            "extraHit": 0,
            "prize": null,
            "combinationHits": 0
          }
        ]
      }
    ]
  }
}
```

字段说明：

- `summary.bestPrize`：所有期次、所有号码中的最高奖级；未中奖为 `null`。
- `summary.winningDraws`：至少有一注中奖的期数。
- `summary.winRate`：`winningDraws / drawCount`，保留 4 位小数。
- `matches[].combinationHits`：该期命中的组合注数，单式为 0 或 1。
- `prize.estimated`：浮动奖估算标记。

### 6.3 错误码

| 场景 | HTTP | 业务码 |
|---|---:|---|
| 未登录 | 401 | 40100 |
| 玩法不存在 | 404 | 40400 |
| 窗口非法 | 422 | 42200 |
| 号码不合法 | 422 | 42201 |
| 展开组合数超过 10000 | 400 | 40002 |
| 历史数据为空 | 200 | 0，返回空结果 |

## 7. 后端实现

新增模块：

- `backend/app/matches/service.py`：窗口查询、组合展开、逐期匹配、汇总。
- `backend/app/matches/views.py`：`POST /api/v1/prize-matches`。
- `backend/app/games/views.py`：新增 `GET /api/v1/games/{game}/prizes`。
- `backend/app/schemas.py`：匹配请求/响应模型。

处理流程：

1. 校验登录和玩法。
2. 校验窗口，默认 50，范围 1–300。
3. 用现有 `validate_bet` 校验每注号码结构。
4. 展开组合，超过上限直接拒绝。
5. 查询最近 `window` 期开奖记录。
6. 逐注、逐期计算命中数，调用 `evaluate`。
7. 汇总最佳奖级、中奖期数和奖级次数。
8. 日志记录用户、玩法、窗口、注数、耗时，不记录号码明细和令牌。

性能：

- 50 期 × 单注为常数级开销。
- 复式上限 10000 注 × 50 期 = 50 万次集合交集，使用 `set` 预计算和位掩码可控制在可接受范围。
- 不写数据库，不需要迁移。

## 8. 前端交互

### 8.1 结果区

在现有结果面板增加“历史命中”区域：

- 默认窗口 50，提供 50 / 100 / 200 / 300 切换。
- 生成号码成功后自动请求一次，窗口切换后重新请求。
- 顶部摘要：最佳奖级、中奖期数、总期数、各奖级次数。
- 明细列表：期号、日期、命中数 `主+副`、奖级徽标、奖金。
- 未中奖行使用中性灰，不使用低透明度。
- 浮动奖显示 `≈` 和“估算”标记。
- 请求失败展示错误提示，保留已生成号码。

### 8.2 规则展示

- 结果区提供“中奖规则”按钮，打开对话框。
- 规则表按当前玩法展示：奖级、条件、奖金、是否估算。
- 规则数据来自 `GET /api/v1/games/{game}/prizes`。
- 规则表不写真实游戏名称，不出现“必中”“稳赚”等表述。

### 8.3 状态与可访问性

- 加载中：骨架或 `正在匹配最近 50 期`。
- 空数据：`暂无历史开奖数据`。
- 无中奖：`最近 50 期未命中奖级`。
- 奖级颜色不能作为唯一信息，必须同时显示奖级文字。
- 键盘可操作窗口切换和规则对话框。

## 9. 测试与验收

### 9.1 后端

- 红蓝玩法 6+1、6+0、5+1、5+0、4+1、2+1、0+1 边界。
- 前后玩法 5+2、5+1、4+2、3+1、2+2、0+2 边界。
- 单注、多注、复式组合、胆拖组合。
- 默认窗口 50，边界 1 和 300，超过 300 返回 422。
- 组合数超过 10000 返回明确错误。
- 浮动奖 `estimated=true`。
- 未登录返回 401。

### 9.2 前端

- 生成后自动展示最近 50 期匹配结果。
- 切换窗口触发新请求。
- 未中奖、部分中奖、多奖级汇总渲染正确。
- 规则对话框展示当前玩法规则。
- 估算奖级有明确标记。

### 9.3 验收标准

- 用户能在结果区看到“最近 50 期最佳奖级”和逐期奖级。
- 奖级判定与回测使用同一规则，不出现两套结果。
- 50 期单注匹配在 1 秒内返回。
- 不出现“预测中奖”“必中”“稳赚”等文案。
- `pnpm check:terms`、`pnpm lint`、`pnpm typecheck`、`pnpm build`、后端 `ruff` 与 `pytest` 通过。

## 10. 实施顺序

1. 后端规则接口 `GET /api/v1/games/{game}/prizes`。

4. 前端结果区“历史命中”与规则对话框。
5. 前端测试与联调。
