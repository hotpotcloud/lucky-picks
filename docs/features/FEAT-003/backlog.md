# FEAT-003 候选需求：从开源调研沉淀的迭代清单

> 来源：`docs/features/FEAT-002/research-open-source.md`。本文件只做需求池，未排期；进入开发前需单独走 FEAT-003 需求与设计。
> 原则：任何功能都不得暗示「提高中奖率」；回测与覆盖率必须可验证。

## 优先级说明

- P0：合规/数据正确性相关，必须优先。
- P1：用户价值高、与 FEAT-002 架构兼容、工作量可控。
- P2：探索型或成本较高，视资源排期。

## 重点需求说明

### F3-001 数据多源校验与纠错（P0）

- 官方主源 + 备用官方页面/人工校正；期号、日期、号码交叉校验。
- 差异进入「待确认」表，不直接覆盖；保留变更历史。
- 验收：构造冲突数据时能标记差异；人工确认后更新；统计/回测使用确认后的版本。

### F3-002 走势图与遗漏可视化（P1）

- 号码走势矩阵：横轴期号、纵轴号码、命中点连线；遗漏值色块。
- 支持红蓝玩法/前后玩法分区切换；移动端手势。
- 验收：最近 100 期渲染 < 1s；与统计接口数据一致；颜色之外有文字/图形区分。

### F3-003 多策略/多模型对比（P1）

- 同一回测窗口并排展示各策略/模型：命中率、ROI、置信区间、与随机基线差值。
- 排行榜标注样本量与「是否显著」；不显著时明确写「未发现优势」。
- 验收：结果可复现；随机基线始终在列；禁止只展示最优一次。

### F3-005 覆盖设计/旋转矩阵（P1）

- 输入号码池与预算，输出全复式/缩水方案，展示「池中命中 k 个时保证的奖级」。
- 预置常见 wheel 表 + 贪心覆盖生成；与规则引擎联动计算注数/金额。
- 验收：保证条件可被程序验证；金额不超限；说明「保证覆盖不等于中奖」。

### F3-007 模型实验框架（P2）

- 统一 `Strategy` 接口，模型输出分数/概率；强制 walk-forward、随机基线、置信区间。
- 只有通过「样本外显著优于基线」门槛才允许上线展示；否则仅研究页可见。
- 验收：新增模型不影响主流程；回测报告含负面结论；不训练用户数据。

## 明确不做

- 不提供「必中」「稳赚」「提高中奖率」类功能或文案。
- 不做自动购买、代购、支付、兑奖。
- 不接入未授权数据源或破解接口。
- 不用单次命中/幸存者偏差做宣传。
